# CRM الموحّد لإدارة وأتمتة بوتات تليجرام

منصة CRM كاملة تستقبل رسائل عملاء تليجرام، تعرضها في لوحة تحكم موحّدة، وتدير مسار المبيعات والردود الآلية — **بدون أي خدمة مدفوعة وبدون أي تبعية خارجية**.

| ما في دليلك الأصلي | ما يقابله هنا (مجاني ومفتوح) |
|---|---|
| Airtable / NocoDB (قاعدة البيانات) | SQLite مدمج في Node — جداول: users و messages و deals |
| Make.com (محرك الأتمتة) | `bot.js` — استقبال التحديثات + قواعد Reply تلقائي |
| Softr.io (لوحة التحكم) | لوحة ويب مدمجة (`public/`) — إحصائيات + رسوم + صلاحيات |

## المزايا

- **صندوق وارد موحّد**: كل رسائل العملاء مع عدّاد غير المقروء
- **رد مباشر** من اللوحة يُرسل للعميل عبر تليجرام
- **حالات العملاء**: جديد → مهتم → تم التواصل → عميل / مفقود
- **خط مبيعات مرئي** (Pipeline) بأربع مراحل مع القيمة المالية
- **ردود آلية**: قاعدة "الكلمة المفتاحية → الرد" تنفَّذ فوراً (Router بديل Make)
- **إحصائيات حيّة**: رسائل واردة/صادرة لآخر 14 يوم، عملاء جدد، أعلى تفاعلاً
- **تحديث فوري** (SSE) — الرسالة الجديدة تظهر باللوحة بدون تحديث الصفحة
- **صلاحيات**: مدير (admin) يضيف موظفين (agents) ويديرهم

## الربط بمنصّة ZeidexSoft (جسر محرّك الأتمتة)

لا يحتاج هذا الـCRM توكن بوتك ليشتغل مع متجرك على المنصّة: المنصّة نفسها تُصدِر
أحداثاً موقَّعة لكل عميل ورسالة وطلب (`/wf` — نفس المسار الذي يأخذ n8n
وActivepieces)، وهنا تصير تلك الأحداث **عملاً مرئياً**:

```
منصّتك (worker/bots.ts)                 هذا الـCRM
  عميل جديد / رسالة / طلب  ──POST /api/bridge (x-zeidex-signature)──▶  عميل + رسالة + صفقة
  موظف يرد من اللوحة        ──POST /api/wf/<botId> (Bearer)──▶  البوت يُسلّم الرد للعميل
```

الربط بثلاثة متغيّرات — لا سرّ بوت، ولا نسخ روابط:

```bash
BRIDGE_TOKEN="<التوكن المشتق للبوت>" BRIDGE_BOT_ID="<معرّف البوت>" PLATFORM_ORIGIN="https://zeidexsoft.com" node server.js
```

ثم في بوتك على المنصّة، أمر واحد يوجّه الأحداث إلى هنا:

```
/wf https://<عنوان-هذا-السيرفر>/api/bridge
```

حالة الجسر ظاهرة في شريط اللوحة: **جسر المنصّة** (أحداث + ردود عبر المنصّة)،
**أحداث فقط** (تُستقبل الأحداث والردود تخرج من توكن البوت المحلي)، أو **محلي**.

| الحدث الوارد | ما يبنيه |
|---|---|
| `customer_new` | عميل جديد + ملاحظة نظام |
| `message` | رسالة واردة، ثم قاعدة ردّ آلية إن طابقت |
| `order` | صفقة في مرحلة «رابحة» بقيمة النجوم + تحويل العميل إلى «عميل» |

## التشغيل

المتطلب: Node.js 22.5+ (لا يحتاج `npm install`).

```bash
npm test    # 12 فحصاً: المنطق، الجسر، والسيرفر كاملاً على منفذ حقيقي
```

```bash
cd CRM

# 1) شغّل اللوحة بدون بوت (وضع محلي)
node server.js
# ثم افتح http://localhost:8787
# المستخدم: admin — كلمة المرور: admin123

# 2) بيانات تجريبية (اختياري)
npm run seed
```

### ربط بوت تليجرام

1. أنشئ بوتاً من [@BotFather](https://t.me/BotFather) وانسخ التوكن.
2. شغّل مع التوكن:

```bash
BOT_TOKEN="123456:ABC..." node server.js
```

3. ابدأ محادثة مع البوت — ستجد الرسائل فوراً في اللوحة.

**وضع الاستقبال**: افتراضياً `long polling` (لا يحتاج دومين). لو عندك دومين عام:

```bash
BOT_TOKEN="123:ABC" BOT_MODE=webhook TELEGRAM_WEBHOOK_SECRET="<سر-عشوائي>" node server.js
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://YOUR-DOMAIN/api/telegram/webhook&secret_token=<SECRET>"
```

### متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `8787` | منفذ السيرفر |
| `BOT_TOKEN` | — | توكن البوت؛ بدونه يعمل الوضع المحلي |
| `BOT_MODE` | `poll` / `webhook` | `off` يوقف البوت |
| `TELEGRAM_WEBHOOK_SECRET` | — | حماية نقطة الـ webhook |
| `ADMIN_USER` / `ADMIN_PASS` | `admin` / `admin123` | حساب المدير الأول |
| `DB_PATH` | `./crm.db` | مسار قاعدة البيانات |
| `BRIDGE_TOKEN` | — | توكن الجسر المشتق للبوت (من `/wf`)؛ بلا قيمة لا جسر |
| `BRIDGE_BOT_ID` | — | معرّف البوت على المنصّة |
| `PLATFORM_ORIGIN` | `https://zeidexsoft.com` | تُرسل إليه الردود لتصدر من البوت |

## البنية

```
CRM/
├── server.js      # HTTP + API + مصادقة + SSE + ثابت الملفات
├── db.js          # SQLite: users, messages, deals, rules, agents, sessions
├── crm.js         # منطق العمل: العملاء، الرسائل، الصفقات، الإحصائيات
├── bot.js         # تليجرام: polling/webhook + الرد الآلي
├── events.js      # بث الأحداث الفورية
├── seed.js        # بيانات تجريبية
└── public/        # اللوحة (HTML/CSS/JS خالص — بدون build)
```

## أهم الـ Endpoints

| الطريقة | المسار | الوظيفة |
|---|---|---|
| POST | `/api/login` | دخول (يعيد token) |
| GET | `/api/stats` | الإحصائيات والرسوم |
| GET | `/api/users?q=&status=` | قائمة العملاء |
| GET | `/api/users/:id` | عميل + محادثته + صفقاته |
| PATCH | `/api/users/:id` | تعديل الحالة/الاسم/الملاحظة |
| POST | `/api/users/:id/messages` | رد على العميل (يُرسل لتليجرام) |
| GET/POST | `/api/deals` | صفقات خط المبيعات |
| PATCH/DELETE | `/api/deals/:id` | نقل مرحلة / حذف |
| GET/POST | `/api/rules` | قواعد الرد الآلي |
| GET | `/api/events` | بث فوري (SSE) |
| POST | `/api/telegram/webhook` | استقبال تحديثات تليجرام |

## أمان

- كلمات المرور `scrypt` + salt، الجلسات token عشوائي صلاحية 7 أيام
- كل endpoints محمية بـ Bearer token (ما عدا login و webhook)
- `GET /api/events` و webhook يدعمان مصادقة الرابط/السر
- قاعدة SQLite بـ WAL — تقراء وكتابة متزامنة

> ⚠️ غيّر كلمة مرور `admin123` فوراً عبر `ADMIN_USER/ADMIN_PASS` عند أول تشغيل.

## رحلة الرسالة (من تليجرام إلى اللوحة)

```
عميل يكتب في تليجرام
   └─> bot.js يستقبل (polling أو webhook)
        ├─> users: تسجيل/تحديث العميل  ──> SSD/SSE ──> اللوحة تتحدّث فوراً
        ├─> messages: حفظ الرسالة (in)
        └─> قاعدة مطابقة؟ ──> sendMessage الرد (out)
موظف يرد من اللوحة
   └─> POST /api/users/:id/messages ──> sendMessage للعميل + حفظ (out)
```

## ملاحظات

- قاعدة البيانات (`crm.db*`) محلية ولا تُرفع — أضفها إلى `.gitignore` قبل أي commit.
- الجسر بلا حالة: كل حدث مستقل، وإعادة تشغيل السيرفر لا تفقد رسائل (SQLite + WAL).
